Plan-Retrieve-Verify: An LLM-Driven Framework for Long-Video Audio-Visual Evidence Reasoning
一作1st authorCCF AACM MM 2026工具调用智能体 · 过程监督Tool-use agent · process supervisionPDF ↗Code ↗
问题Problem长视频问答要在画面、语音和环境音之间多轮找证据；现有方法检索一次就作答，不检查证据是否支持结论。Long-video QA needs several rounds of evidence search across frames, speech and ambient sound; existing methods retrieve once and answer without checking that the evidence supports the conclusion.
方法ApproachLLM 控制器执行“计划 → 检索 → 验证”工具调用闭环，证据不足或矛盾时拒答；用 5 类反事实扰动轨迹直接监督规划、选工具和验证等中间决策。An LLM controller runs a plan → retrieve → verify tool-calling loop and abstains when evidence is missing or contradictory; counterfactual trajectory supervision with five perturbation types trains the intermediate planning, tool-selection and verification decisions.
CALM-TS: Risk-Controlled LLM Labeling for Time-Series via Calibrated Selective Gating
一作1st authorCCF AKDD 2026可信监督信号Trustworthy supervisionPDF ↗DOI ↗Code ↗
问题ProblemLLM 能给时间序列事件打弱标签，但错误率没有上界，不能直接当训练数据。LLMs can weakly label time-series events, but their error rate has no bound, so the labels cannot be used directly as training data.
方法Approach在提示措辞、采样温度、上下文窗口三个维度上探测模型分歧，校准门控决定接受或拒标，给出有限样本保证：标注错误率不超过预设上限。Probe model disagreement across prompt wording, sampling temperature and context window; a calibrated gate accepts or abstains with a finite-sample guarantee that the labeling error rate stays below a preset bound.
CodeFault: Predicting Fault Risks from Code Changes via Multi-Modal Learning
一作1st authorCCF AASE 2026PDF ↗DOI ↗Code ↗
问题Problem即时缺陷预测只看代码变更，日志异常检测只看运行时行为，两者脱节，故障发现滞后。Just-in-time defect prediction sees only code changes and log anomaly detection sees only runtime behavior, so faults are found late.
方法Approach以两级故障谱（4 个粗类、8 个细类）为共享空间对齐代码变更与运行日志，并用故障谱一致性引导 token 级跨模态注意力；蒸馏出只用代码的版本，可在提交前部署。Align code changes and runtime logs in a shared two-level fault taxonomy (4 coarse, 8 fine categories) and use taxonomy agreement to guide token-level cross-modal attention; a distilled code-only variant runs before commit.
ProgV-Trace: An LLM-Driven Verification Framework for Evidence-Grounded Video Misinformation Attribution
一作1st authorCCF AACM MM 2026可执行验证 · 蒸馏Executable verification · distillationPDF ↗Code ↗
问题Problem视频虚假信息常由真实画面、伪造字幕和篡改语音拼成；现有检测器只给真假判定，指不出是哪个元素让叙述变假。Video misinformation mixes real footage with forged captions or altered speech; detectors give a true/false verdict but cannot say which element makes the claim false.
方法ApproachLLM 生成类型化 DSL 验证程序，构建多模态溯源图，用最小反事实干预量化每个元素的责任；再把推理蒸馏到小型验证器，部署时不调用 LLM。An LLM writes verification programs in a typed DSL, builds a multimodal provenance graph and scores each element's responsibility with minimal counterfactual interventions; the reasoning is distilled into a small verifier that needs no LLM at deployment.

递归自我改进（RSI）Recursive Self-Improvement (RSI)

智能体从自身 rollout 中获得经验、经验证后回灌后训练，形成 rollout → 经验 → 验证 → 后训练 → 更强策略的闭环。Agents gain experience from their own rollouts, verify it, and feed it back into post-training: the rollout → experience → verifier → post-training → better policy loop.

ScholarForge：面向科研全生命周期的 Agentic 工作流系统ScholarForge: An Agentic Workflow System for the Full Research Lifecycle
2025.02 – 至今2025.02 – Present
个人主导，独立设计与维护。基于 Claude Code 构建的 AI-native 科研生产系统，以 Skill + Subagent + Workflow 三层架构覆盖立项到终稿，支撑 40+ 个论文仓库的日常研发。Sole designer and maintainer. An AI-native research production system built on Claude Code, with a three-layer Skill + Subagent + Workflow architecture from planning to camera-ready; supports daily work on 40+ paper repositories.
  • 阶段化技能（Stage-gated Skill）：把立项、实验、写作、出图、验证、投稿、评审回复、终稿 8 个阶段（P0–P7）建模为带准入判据与验收门（acceptance gate）的 Claude Code Skill，按请求只加载相关阶段（progressive disclosure）；7 个回归评测用例，规则变更后用插件评测复测，防止行为回退。Stage-gated skill: the 8 stages (P0–P7: planning, experiments, writing, figures, validation, submission, author response, camera-ready) are modelled as a Claude Code skill with entry criteria and acceptance gates; a request loads only the stage it touches (progressive disclosure); 7 regression evals re-run with plugin evals after each rule change to prevent behavioural regressions.
  • 多智能体编排（Orchestrator–Worker）：11 个代码化 workflow（并行扇出、流水线、结构化输出 schema），覆盖进度巡检、内部评审、模拟审稿、视觉审计、对抗式自审、投稿合规门禁、跨仓库缺陷横扫、评审回复装配与终稿核验；按角色绑定模型档位，并发上限受控。Orchestrator–worker multi-agent workflows: 11 workflows in code (parallel fan-out, pipelines, structured-output schemas) for progress roll-up, internal review, simulated review, visual audit, adversarial self-audit, submission compliance gate, cross-repository defect sweep, author-response assembly and camera-ready checks; a model tier is bound to each role and concurrency is capped.
  • 数据溯源与可复现（Provenance）：论文中每个数值绑定唯一宏与运行产物键（artifact key），形成从实验到正文的数据血缘；生成物要求字节级可复现，模型不生成任何数据；投稿前自动检查匿名化、参考文献真实性（只从 DOI / arXiv API 生成）、版面与图片合规。Provenance and reproducibility: every number in a paper is bound to one macro and one run-artifact key, giving data lineage from experiment to text; generated files must be byte-reproducible and models never generate data; pre-submission checks cover anonymity, reference validity (entries built only from DOI / arXiv APIs), layout and figure compliance.
  • 双模型交叉评审：Claude 按官方审稿表做多审稿人独立打分（LLM-as-a-Judge），与 GPT 审稿意见合并去重，迭代到修复清单闭环。Two-model cross review: Claude scores the paper as several independent reviewers on the official form (LLM-as-a-Judge); the findings are merged and de-duplicated with GPT reviews and iterated until the fix list is closed.
  • 评测驱动的配置选择：出图配置经盲评确定（2 个任务 × 6 种模型与推理强度组合，先登记决策规则再揭盲）；基于 manim 与本地 TTS 的 Skill 自动生成论文讲解视频。Eval-driven configuration: the figure configuration was chosen by a blind benchmark (2 tasks × 6 model-effort settings, decision rule registered before unblinding); a manim + local TTS skill generates paper explainer videos.

  • 跨机接力（Baton Hand-off）：以状态机与交接协议在工作站与 GPU 服务器之间迁移同一篇论文的流水线：四步握手、失败即停（fail-closed）、属主写锁防止并发写。Baton hand-off: a state machine and hand-off protocol move one paper's pipeline between the workstation and GPU servers, with a four-step handshake, fail-closed behaviour and an owner write lock against concurrent writes.
  • 移动端远程控制：自研 Telegram 主通道加 ntfy 兜底的遥控 Bot，cron 守护实现 5 秒级崩溃自愈，任务完成与异常主动推送。Mobile remote control: a self-built remote-control bot with Telegram as the main channel and ntfy as fallback; a cron guardian restarts it within 5 s after a crash, and completions and failures are pushed to the phone.
  • 护栏与钩子（Guardrails）：PreToolUse 钩子在执行前拦截高危命令，Stop 钩子跨机同步配置，post-commit 钩子自动推送；输出风格按简化技术英语（ASD-STE100）约束全部文字产出。Guardrails and hooks: a PreToolUse hook blocks high-risk commands before execution, a Stop hook syncs configuration across machines, and post-commit hooks auto-push; an output style holds all written output to Simplified Technical English (ASD-STE100).
